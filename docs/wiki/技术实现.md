# 技术实现

## 总体：纯静态、零依赖、零运行时构建

开发时 `scripts/build.mjs` 在本地生成产物并提交入库；部署后浏览器拿到的就是纯 HTML/CSS/JS——没有框架、没有包管理器、没有构建步骤、没有第三方运行时。

- 唯一真实页面：`index.html`（由 `templates/page.html` + `assets/js/sites.js` + `scripts/icons.mjs` 生成）
- 单文件便携版：`SimpleSearch.html`（由 `index.html` 内联生成）
- 两个 0 秒重定向壳：`SimpleSearch-Light.html` / `SimpleSearch-Dark.html`（老链接兼容）
- PWA：`manifest.webmanifest`（手写）+ `sw.js`（由 `templates/sw.js` 注入版本号与 precache 列表生成）

## 经典脚本，不是模块

`assets/js/*.js` 全部是 IIFE + `globalThis` 的普通脚本（ES2015+ 语法，不用 `import` / `export`、不用 `type="module"`），不需要打包：

所以既能被浏览器直接加载，也能被 Node 直接 `import()` 做单元测试。

脚本分工（11 个）：

| 文件 | 职责 |
|---|---|
| `sites.js` | 单一数据源：`SS.sites`（33 个内置站点）+ `SS.siteGroups` + `SS.engines` |
| `search.js` | URL 构建、`resolveSite` / `resolveBang`、`encodeURIComponent` 编码 |
| `suggest.js` | 联想列表（本地匹配 + 远程结果合并） |
| `history.js` | 最近 10 条搜索历史 |
| `theme.js` | 主题三态 + 19 组主题色（`data-theme` / `data-color`） |
| `remote.js` | 百度 JSONP 联网联想（可插拔 provider、超时降级、缓存） |
| `input.js` | 输入框交互、清除按钮、联想键盘操作 |
| `sites-store.js` | 自定义站点 / 排序 / 配置导入导出的纯数据层（storage 注入，可单测） |
| `sites-admin.js` | 「我的站点」「常用排序」两个对话框的 UI 层 |
| `pwa.js` | Service Worker 注册、PWA 安装引导、新版本提示 snackbar |
| `app.js` | 启动装配、深链、分类筛选、抽屉/对话框、涟漪 |

## 构建产物与「产物漂移」

- `npm run build` 生成 5 个文件；`npm run build --check` 只校验是否最新。
- CI 先跑 `npm run build` 再 `git diff --exit-code -- index.html SimpleSearch.html SimpleSearch-Light.html SimpleSearch-Dark.html sw.js`，改数据忘重建会直接失败。
- `validate` 静态检查 32 项（DOM 契约、可访问性、体积门禁、产物一致性、社交 meta、PWA 安装/更新 DOM 等）。

## PWA / 离线

- `manifest.webmanifest`：`standalone`、192/512 图标、`start_url` 指向 `index.html`。
- `sw.js`（build 生成，约 2.4 KB）：`install` 预缓存 16 项静态资源 → `activate` 清旧缓存 + `claim` → `fetch` 只处理同源 GET（导航请求回退缓存的首页，跨域请求直接放行不缓存）。
- `file://` 下不注册；升级版本后旧缓存自动清理，不会出现页面与缓存版本对不上。
- SW 是后台注册的，不计入首屏；manifest 只在安装时用。
- **安装引导**：`assets/js/pwa.js` 监听 `beforeinstallprompt`，满足安装条件时设置面板出现「安装到桌面」行，点「安装」走浏览器安装流程；已安装或浏览器不支持时该行保持隐藏，不打扰。
- **新版本提示**：已安装的 PWA 有新 Service Worker 接管时，底部弹 snackbar「新版本已就绪」+「刷新 / 稍后」；刷新会加载新版，「稍后」只在本次会话不再提示。
- **iPhone 安全区**：`viewport` 用 `viewport-fit=cover`，顶栏 / 侧栏 / 设置面板 / snackbar 用 `env(safe-area-inset-*)`，全屏 PWA 顶部不被状态栏压住。

## 单文件便携版

`SimpleSearch.html` 由 `index.html` 内联生成：

- 3 个 `<style>`、11 个经典脚本 + 防闪烁脚本 + `window.__SS_SINGLE_FILE` 标记
- favicon 转 data URI，移除 manifest / apple-touch-icon
- `app.js` 看到 `__SS_SINGLE_FILE` 就不注册 SW

因此它**零外部请求**、双击即用；代价是没有 PWA 安装 / 离线缓存，改一个字要整页重下，体积略大（重复内容无法跨文件缓存）。

| 版本 | 请求数 | PWA | 体积 |
|---|---|---|---|
| `index.html`（多文件） | 17 个（零第三方，无图片） | ✅ | 首屏约 206.8 KB / gzip 58.9 KB（预算 212 KB） |
| `SimpleSearch.html`（单文件） | 1 个 | ❌ | 207.0 KB / gzip 50.4 KB（上限 260 KB） |

## 社交分享预览（meta）

页面 head 里有 `og:url`、`og:image`（1200×900 截图）、`og:image:width/height`、`og:site_name`，以及 `twitter:card=summary_large_image`、`twitter:title/description/image`。`build` 会注入**绝对 URL**（`https://breathiness.github.io/SimpleSearch/...`），所以分享到聊天/社交平台时能显示标题 + 描述 + 缩略图；单文件版也使用绝对 URL，分享出去同样有图。

## 主题三态与主题色

- `<html data-theme-default="auto">`；首屏内联脚本按「`?theme=` 老参数 → `ss.theme`（只表示显式选择）→ `prefers-color-scheme` → 浅色」决定主题，避免闪烁。
- 选「跟随系统」时删除 `ss.theme`（不写 `auto`），系统深浅色切换实时跟随。
- 19 组 MDUI 主色存在 `tokens.css`：一层色值（`--c-500/700/200`）+ 一层语义变量（`--primary` / `--primary-bg` / `--focus-ring` / `--on-primary`），换 `data-color` 即换整站主色，零请求；首屏脚本与 `data-theme` 同时设置，不闪默认色。
- 浅色主题用 700 档、深色用 200 档；浅色系主色的 `--on-primary` 自动用深色文字。

## 站点图标：内联 SVG sprite，零图片请求

- 一个隐藏的 `<svg class="icon-sprite">`，每个图标一个 `<symbol id="i-xxx">`，按钮里 `<use href="#i-xxx">` 引用——浏览器不下载任何图片。
- 当前 **32 个 symbol**：22 个站点图标 + 3 个 UI 图标（menu/settings/close）+ 1 个 logo + 6 个分类图标；另有 11 个站点用 `icon: 'cat-<group>'` 复用分类图标，不重复占 symbol。
- 24×24、`fill="none"` + `stroke="currentColor"`，颜色跟随主题文字色。
- 图标数据在 `scripts/icons.mjs`，是 **dev-time 资产**：只在构建时被 Node 读取，运行时不加载。
- 没配图标的站点退化为首字符 monogram，零额外成本。

### 为什么不用 favicon 服务 / 自托管 PNG

| 做法 | 代价 |
|---|---|
| 外链 favicon 服务 | 每张图标一个跨域请求 + DNS/TLS 建连；服务挂或断网就空白；还会把访问站点清单暴露给第三方 |
| 自托管图片 | 每张一个请求，还要处理缓存、离线包、DPR 尺寸 |
| emoji | 零字节但风格不统一、跨系统字形差异大 |
| **内联 SVG sprite** | 零额外请求、零额外文件，代价只是 HTML 大一点（gzip 后约 1.3 KB） |

## 性能与体积

- 2023 年在原项目上实测：GitHub Pages 在线版加载完成 **656 ms**，本地双击 **3 ms**。
- v2 之后仍是纯静态 + 零依赖：没有框架、网络字体、统计脚本；单页静态资源约 **196 KB 未压缩 / gzip 约 56 KB**。
- 首屏实测 **17 个请求、零第三方**：HTML 1 + CSS 3 + JS 11 + favicon 1 + 浏览器按 apple-touch-icon 惯例抓取的 PWA 图标 1（属预期）；**没有一张站点图片**。
- 加图标那一轮：未压缩体积 +9 KB，但 **gzip 只多约 2.1 KB**——SVG sprite 压缩率很高。
- 体积由 `validate` 按磁盘产物硬校验（212 KB / 单文件 260 KB），超了 CI 直接红。

## 单一数据源与「不留两套页面」

站点只写在 `sites.js` 一处；页面只有一份 `index.html`，明暗两套只是 `tokens.css` 里的 CSS 变量，不会出现「浅色页有、夜间页没有」的漂移。

## 第三方请求与本地存储

- 核心页面与功能零第三方资源（字体用系统字体栈，无 CDN、无统计、无追踪）。
- 唯一例外：**默认开启的联网联想**（`suggestion.baidu.com` JSONP）；关闭后零第三方请求、完全离线。
- `localStorage` 只存 7 个键：`ss.theme`、`ss.color`、`ss.engine`、`ss.history`、`ss.remote`、`ss.customSites`、`ss.order`；隐私模式/禁用存储时自动降级不报错。
- Service Worker 只缓存同源静态资源，跨域请求直接放行、不缓存。
- 搜索本身是浏览器原生表单提交到目标站点，不经过任何中间服务器。

## `file://` 双击可用

下载仓库后直接双击 `index.html` 就能用，不需要起服务器（本地 3 ms 的来源）；两个老 HTML 也会跳到首页；`file://` 下不注册 SW。

## 设计风格

界面观感参考 **MDUI 1 / Material Design 1**：19 组 MDUI 主色（默认靛蓝 `#3f51b5`）、2px 圆角、2/4/8dp 三档 elevation、点击涟漪、下划线输入框、主色 raised 搜索按钮、MD1 菜单式联想下拉；页面骨架照 MDUI 1 文档站（主色顶栏 + 左侧分组导航 + 内容卡片 + 右侧设置抽屉）。

这些**全部是自研手写 CSS**，没有引入 MDUI 库、CDN 或任何第三方资源——「MDUI 1 风格」指视觉语言，不是依赖。
