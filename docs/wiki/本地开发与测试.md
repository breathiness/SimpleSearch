# 本地开发与测试

> 返回 [Wiki 首页](Home) · 开发和贡献细节见仓库的 [CONTRIBUTING.md](https://github.com/breathiness/SimpleSearch/blob/main/CONTRIBUTING.md)

## 环境

需要 Node.js 21+（开发与 CI 实际用 22；`npm test` 的 glob 参数需要 Node ≥ 21）。**不需要 `npm install`**——`package.json` 里没有任何依赖，克隆下来直接跑。

## 命令

| 命令 | 作用 |
|---|---|
| `npm run build` | 由模板 + `sites.js` + `icons.mjs` 生成 5 个产物：`index.html`、`SimpleSearch.html`、两个重定向壳、`sw.js`（**改完站点或模板后必须跑**） |
| `npm test` | 全部单元测试（Node 内置 `node:test`） |
| `npm run validate` | 静态检查 36 项 + 生成产物是否最新 |
| `npm run check` | 构建 + 测试 + 校验（提交前 / CI 都用这个） |
| `npm run serve` | 本地静态服务器，默认 <http://127.0.0.1:8080/> |
| `npm run e2e` | 本机 Edge/Chrome 真实浏览器检查（**CI 的 `e2e` job 也会在 ubuntu Chrome 上跑同一脚本**），截图到 gitignore 的 `artifacts/` |
| `npm run coverage` | 可选：Node 内置覆盖率，阈值 90% 行 / 75% 分支 / 80% 函数（不进 CI 必跑） |
| `npm run check:sites` | 可选：逐站请求 `home` / 搜索地址，报告 OK / WARN / FAIL（需网络，不进普通 CI）；`--strict` 只有 FAIL 退出 1，`--json` 输出纯 JSON |
| `npm run visual` | 可选：视觉回归，与 `tests/visual/` 基线逐像素比较 4 个固定状态（无基线时提示先 `visual:update` 并跳过） |
| `npm run visual:update` | 更新视觉回归基线（改完 UI 后跑，人工确认新截图，再把基线 PNG 一起提交） |

```bash
npm run serve
# 打开 http://127.0.0.1:8080/
```

## CI 会跑什么

`.github/workflows/ci.yml` 在 `push` / `pull_request` 上并行跑两个 job，都是 ubuntu-latest + Node 22、零依赖（不需要 `npm ci` / `npm install`）：

1. **`check`**：`npm run build` → `git diff --exit-code` 检查 5 个生成产物是否漂移 → `npm run check`（构建 + 单元测试 + 静态校验 + 体积硬门禁）。
2. **`e2e`**：`node scripts/e2e.mjs`，用 runner 预装的 Google Chrome（`/usr/bin/google-chrome`）跑真实浏览器检查。只做 DOM / 交互 / 网络断言，**不做截图对比**（视觉回归在本地 `npm run visual`，跨平台字体差异不参与 CI）。

另外 `.github/workflows/site-health.yml` 每周一 01:00 UTC 单独巡检站点，不阻塞 PR。

## 维护三件套

### 每周站点巡检（自动）

- `.github/workflows/site-health.yml` 每周一 **01:00 UTC（北京 09:00）** 检查全部内置站点的 `home` / `search`，也可手动触发（Actions → 站点巡检 → Run workflow，或 `gh workflow run site-health`）。
- 报告始终写进本次运行的 **Actions Summary**（含 OK/WARN/FAIL 汇总与明细）。
- **只有 FAIL 才开 issue**：真坏链时在 `site-health` 追踪 issue 评论 / 新建；FAIL 清零后自动关闭。WARN（反爬 401/403、跨域跳转）只在摘要提示。
- workflow 只用官方 `actions/checkout`、`actions/setup-node` 和 runner 预装 `gh`，不跑 `npm install`。

### 视觉回归（本地按需，不进 CI）

- `npm run visual`：起本地服务器 + headless Edge/Chrome，截 4 个状态（`common-light-1200`、`common-dark-1200`、`mobile-light-390`、`settings-open-1200`），与基线逐像素比较（单通道容差 8，差异像素 > 0.3% 失败），新图与 diff 图写 `artifacts/visual/`。
- 截图前会隐藏设置面板的版本号，基线跨版本稳定。
- 改 UI 流程：改代码 → `npm run visual` 看有无意外变动 → 确认新样子 → `npm run visual:update` → 人工确认 → 提交基线 PNG。
- 不进 CI：不同系统字体渲染差异大，硬比较容易误报。

### 体积硬门禁

- `npm run validate`（及 CI）把体积当硬失败：多文件首屏 > **212 KB** 或单文件 > **260 KB** 直接退出 1。
- 超限怎么办：先优化（删无用 CSS/JS、压缩内联数据）；确实需要更大就**显式提高预算并写清理由**（改 `validate.mjs` 常量 + README/CONTRIBUTING 同步 + PR 说明），不要只改数字不说明。
